# M3.8m bounded targeted-window geometry

Date: 2026-09-19

The previous targeted-window implementation always configured the ScreenCaptureKit
stream and VideoToolbox encoder to the fixed Medal canvas (normally 1920x1080).
For a resizable window whose aspect ratio differs from that canvas, ScreenCaptureKit
correctly preserved the source aspect and left black padding. The retained
16:13--16:15 clips demonstrate this with content rectangles such as 1920x957,
1920x740 and 1920x828 inside 1920x1080 output.

The macOS backend now applies a source-bounded policy only for a
desktop-independent `SCWindow` filter: Medal's Resolution is treated as the
maximum width/height, the source is aspect-fitted, and the fitted dimensions
are used as the encoded canvas. Desktop capture retains its fixed-canvas
letterbox policy. The status diagnostic reports `aspectPolicy:
fit_source_bounded` for this path and exposes requested, fitted and final
dimensions separately.

Build and regression gate:

- Xcode beta CMake build: passed
- macOS CTest: 6/6 passed
- Signed app rebuilt and installed at `/Applications/Medal.app`
- Import/build artifacts: `importer-prepare-m3.8m-window-bounded.json` and
  `m3.8m-window-bounded-development-app-build.json`

A fresh physical F8 clip made after the 16:22 installation is still required
to record the resulting encoded dimensions and verify that the user's current
resized Minecraft window has no synthetic borders. Older clips are explicitly
not used as evidence for this change.
