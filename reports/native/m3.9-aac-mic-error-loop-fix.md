# M3.9 recorder error loop fix

Date: 2026-09-19 (UTC)

## Symptom and diagnosis

The imported Medal renderer repeatedly showed its generic `An error occurred
with the recorder` notification. The native diagnostics traced the repeated
failure to the microphone stream: ScreenCaptureKit supplied a USB microphone
format at 96,000 Hz and the native AudioToolbox path attempted to construct an
AAC converter with a 96,000 Hz AAC output. AudioConverter rejected that
converter with OSStatus `1718449215` (`kAudio_ParamError`). Every failed
microphone sample then called the session-wide failure path, producing another
failed event and another generic renderer notification.

## Implemented correction

- `native/backends/macos/audio_encoder.mm` now fixes the AAC compatibility
  output rate at 48,000 Hz. AudioConverter performs the input resampling from
  device-native rates such as 96,000 Hz.
- A microphone encoder failure now removes only the microphone encoder, records
  the error and publishes one `microphone_encoder_failed` event per capture.
  Display and system-audio capture remain alive when the microphone path is
  unavailable.
- Session-wide `fail` transitions are idempotent, so a system-audio or other
  terminal failure cannot generate an unbounded sequence of identical events.
- The helper translates the single microphone failure into the original
  Medal `audio-device-access-denied` recorder error shape. It does not claim
  that microphone capture succeeded.

## Reproduction/verification prerequisite

Use the isolated authenticated profile and the normal Medal Desktop route.
Enable the microphone in Medal settings, start Desktop capture, make one
physical hotkey clip, and validate the resulting MP4 through AVFoundation,
independent ffprobe and the imported Medal playback path. If microphone
access is revoked, approve the individual signed app prompt/System Settings
entry; do not reset TCC or disable macOS security. A microphone failure should
now produce one specific error rather than a recurring generic toast.
