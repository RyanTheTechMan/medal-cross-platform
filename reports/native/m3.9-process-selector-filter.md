# M3.9 manual process-selector filtering

Date: 2026-09-20

## Result

The original Medal Game selector now receives only processes marked
`manual_selectable` by the native macOS adapter. Normal AppKit applications
(`NSApplicationActivationPolicyRegular`) remain available to the user. Java-
launched Minecraft and known A Dance of Fire and Ice targets are explicit
exceptions when they own a real ScreenCaptureKit window, because a game can be
captureable without presenting a normal Dock identity. Accessory/prohibited
helpers and agents such as Dock, AutoFill, WindowManager, Control Center,
accessibility agents, and Electron helpers are omitted.

This is intentionally not a Dock-only filter: Dock presence is a useful proxy
for normal user applications, but it would hide legitimate game processes
whose launcher/runtime is not a regular Dock application. Automatic game
detection still receives the complete typed native process model; the filter is
applied only when translating `getActiveProcesses` for the manual UI.

## Live UI evidence

The rebuilt `/Applications/Medal.app` was opened with the isolated authenticated
profile. The original Game selector accessibility tree showed these normal
user-facing entries while no internal processes were present:

`ChatGPT`, `Dia+`, `Discord PTB`, `Finder`, `GitKraken`, `LucidLink`,
`Messages`, `Notes`, `Spark Desktop (Beta)`, `Terminal`, and `Termius Beta`.

The previously observed selector list containing `Dock`, `AutoFill`,
`WindowManager`, `AccessibilityVisualsAgent`, and other helper processes was
not present after the filter build.

## Remaining coverage

The selector policy is implemented and live-checked. A physical run with
Minecraft and A Dance of Fire and Ice open remains useful to verify that the
explicit non-Dock exceptions appear with their friendly names; target launch,
window recreation, fullscreen transitions, and source-disappearance handling
remain separate lifecycle gates.
