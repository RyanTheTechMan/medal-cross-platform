Host: macOS 27.2 arm64, Apple M5 Max  
Toolchain: Xcode beta 27B5019j / SDK 27.2

## Implementation

- The host remains `com.squirrel.medal.medal`; the nested recorder remains
  `com.squirrel.medal.medal.recorder`. Both are signed by the fixed Apple
  Development identity/team `32396A31EA92D7AB513FC0B8EFB8F22E3CC83320` /
  `XDB9K8JX58`.
- The host and recorder now carry the explicit
  `com.apple.security.device.audio-input` entitlement. This is required for
  hardened-runtime TCC attribution when the host delegates microphone access
  to the recorder; it is not user consent.
- On the first native-port connection, the imported main process asks the
  signed helper for status and invokes the normal macOS request APIs for
  microphone and Screen Recording when status is `not_determined`.
- A persisted denial produces an original Medal recorder error and opens the
  documented Microphone System Settings pane. Capture continues without the
  microphone rather than silently substituting system audio or failing the
  video stream. A later capture retry re-evaluates TCC status.
- Camera is not requested during onboarding because it is optional and only
  required when a camera overlay is enabled. Carbon hotkeys do not require
  broad Input Monitoring access.

The signed app was installed at `/Applications/Medal.app`. Accessibility
inspection of the real System Settings panes showed `Medal.app` enabled in:

- Privacy & Security → Microphone
- Privacy & Security → Screen & System Audio Recording

The helper does not need a second user-facing row: the TCC log identifies the
Electron host as the responsible signed identity and the recorder as the
requesting/accessing nested identity. Before this fix, the log explicitly said
the responsible host lacked `com.apple.security.device.audio-input`; that
failed evidence is retained in the session log. After the signed rebuild, TCC
reported an allowed hardened-runtime prompt policy and the `Medal.app` rows
appeared enabled.

The latest physical hotkey diagnostics still show
`captureDiagnostics.audio.microphone.enabled=false`; that is the existing
Medal setting state, not proof of microphone capture. A fresh normal UI clip
with Medal's microphone setting enabled is still required to verify AAC
microphone packets and audible playback.

## User prerequisite

The user must approve the ordinary macOS prompt or enable the signed `Medal.app`
entry in System Settings. Rebuilds must keep the same bundle IDs and team
identity for the grant to remain attributable. No TCC database edit, `tccutil`
reset, SIP/Gatekeeper change, or global security relaxation is used.
