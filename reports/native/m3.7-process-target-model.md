Date: 2026-09-19  
Baseline: `68bad7f` (`Complete original desktop capture UI round trip`)  
Scope: automatic process discovery and the native identity used by targeted ScreenCaptureKit capture.

## Evidence from the original imported client

The authenticated isolated profile's original Game chooser requested `getActiveProcesses` and rendered the following two game-related entries while the user had both games open:

- `ADanceOfFireAndIce` (class `com.7thbeat.adofai`)
- `java` (the Minecraft process)

The chooser did not require manual registration. Selecting `ADanceOfFireAndIce` caused the original renderer to send `setTargetProcess` with the recovered array-shaped fields. The pre-change helper re-enumerated by the display name and returned `status:failed` with `the selected process is no longer running` at 01:25:12. That is retained failure evidence, not a successful targeted-capture test.

The recovered client handler was traced in the pinned `main.min.js`: a successful `targetProcess` calls `hfe`, which POSTs `/games/requests` with `processName`, `captureType`, `className`, `launchType`, and `captionName`; the returned `gameRequestId` is sent back through the original `setGameRequestId` notification. No invented category database or successful no-op response was added.

## Implementation

`native_port::ProcessIdentity` is now the internal target model. It retains:

- native PID, bundle identifier, executable path/name;
- NSRunningApplication and ScreenCaptureKit application names/identifiers;
- CoreGraphics and ScreenCaptureKit window IDs/titles;
- separate caption/class vectors only at the Medal protocol boundary.

The helper stores this typed identity rather than the Windows-shaped wire DTO. Targeted capture uses the identity-aware `CaptureSession::start_application` overload and matches `SCRunningApplication.processID` first. The original `active_processes` DTO is generated only when answering the imported client. Java-launched processes with a visible title containing `Minecraft` are presented as `Minecraft` while retaining `java`/PID for capture.

The display preview path now has a 900 ms, display-size-aware in-memory cache. `activeDisplays(false)` returns no screenshots and does not call ScreenCaptureKit; `activeDisplays(true)` returns bounded JPEG data URLs without writing private screen images to disk.
